# Deployment & Operations Guide — StudyAI Planner Pro

This guide outlines the steps required to deploy, operate, and maintain the StudyAI Planner Pro application in both local development and production cloud environments.

---

## 1. Prerequisites

To run this application locally or deploy it to production, you require:
- **Node.js**: Version `20.x` or higher (Active LTS recommended).
- **npm**: Version `10.x` or higher.
- **Git**: Installed for version control operations.
- **Google Gemini API Key**: Required for AI-powered planning features (otherwise falls back to local scheduling).

---

## 2. Environment Variables

The application relies on a single client-side environment variable to load the Google Gemini AI engine:

| Variable Name | Description | Required | Default / Fallback |
| :--- | :--- | :--- | :--- |
| `VITE_GEMINI_API_KEY` | Google generativelanguage Gemini API key. | Optional | Falls back to local scheduling algorithm. |

---

## 3. Local Development

To spin up the project locally:

1. **Clone the repository**:
   ```bash
   git clone <repository-url>
   cd StudyPlanner
   ```
2. **Install dependencies**:
   ```bash
   npm ci
   ```
3. **Configure environment keys**:
   Create a `.env` file in the root directory:
   ```env
   VITE_GEMINI_API_KEY=AIzaSyYourGeminiApiKeyHere
   ```
4. **Launch development server**:
   ```bash
   npm run dev
   ```
   The application will run locally at `http://localhost:5173`.

---

## 4. Production Build

To build and preview the optimized production bundle locally:

1. **Build the bundle**:
   ```bash
   npm run build
   ```
   This generates static assets in the `/dist` directory.
2. **Preview production bundle**:
   ```bash
   npm run preview
   ```
   Vite spins up a local server serving the optimized assets at `http://localhost:4173`.

---

## 5. Vercel Cloud Deployment

StudyAI Planner Pro is optimized for Vercel. Follow these steps for production deployment:

### Via Vercel Dashboard:
1. Navigate to **Vercel** (`vercel.com`) and click **Add New Project**.
2. Select your imported Git repository.
3. Configure the build parameters:
   - **Framework Preset**: `Vite` (automatically detected).
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. Expand **Environment Variables** and add:
   - Name: `VITE_GEMINI_API_KEY`
   - Value: `<Your Gemini API Key>`
5. Click **Deploy**. Vercel will build and host your site.

### Via Vercel CLI:
```bash
npm install -g vercel
vercel login
vercel      # Deploys a preview deployment
vercel --prod  # Deploys to production
```

## 6. Rollback Procedure

In case a production release introduces a critical regression:

1. **Vercel Dashboard Rollback**:
   - Go to your Vercel Project Dashboard.
   - Click the **Deployments** tab.
   - Find the last stable deployment.
   - Click the three dots menu on the right and select **Promote to Production**.
   - This instantly routes traffic to the stable build without rebuilding.
2. **Git Rollback**:
   - Revert the main branch to the stable commit:
     ```bash
     git revert HEAD
     git push origin main
     ```
   - Vercel's automated git trigger will build and deploy the reverted code.

## 7. Cache Invalidation

The scheduler caches study plans in `localStorage` to avoid redundant API request costs. If you update the scheduling rules or the prompt structure, you must invalidate these stale cached items.

### Automated Invalidation:
We maintain a constant inside [prompts.ts](file:///d:/Aditya/Web/Projects/StudyPlanner/src/services/prompts.ts):
```typescript
export const PROMPT_VERSION = 'v2';
```
Incrementing this value (e.g. `'v2'` to `'v3'`) automatically alters the cache keys generated by `generateCacheKey` in [gemini.ts](file:///d:/Aditya/Web/Projects/StudyPlanner/src/services/gemini.ts). Any older keys (which contain `v2`) are immediately skipped, forcing the client to request new, optimized plans from the API or local fallback.

## 8. Operational Verifications

### Offline Verification:
1. Open the application in Chrome.
2. Open DevTools (`F12`) and select the **Network** tab.
3. Check the **Offline** checkbox.
4. Attempt to generate a study plan.
5. **Verify**:
   - An "Offline Fallback plan generated" success/warning toast appears at the top right.
   - A red connection offline banner slides in at the top.
   - The scheduler successfully generates the day-by-day plan using the local fallback algorithm.

### Lighthouse Score Audit:
1. Open DevTools and navigate to the **Lighthouse** tab.
2. Select **Navigation** mode and configure **Device: Desktop**.
3. Select all categories (Performance, Accessibility, Best Practices, SEO) and click **Analyze page load**.
4. Review metrics. Performance should achieve **95+**, with Accessibility, Best Practices, and SEO scoring **100**.
